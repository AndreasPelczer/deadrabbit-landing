iMOPS

IN-MEMORY OPERATING PRODUCTION SYSTEM

── iOS Prototyp · Swift · MIT Lizenz ──

WAS IST DAS?

iMOPS ist eine iOS-App (Swift/SwiftUI, ab iOS 17) mit einem MUMPS-inspirierten In-Memory Key-Value Store als Kern. Die Idee: Aufgaben in einer Profiküche so steuern, wie alte Krankenhaussysteme Patientendaten verwaltet haben — schnell, hierarchisch, ohne Overhead.

Der Kern ist ein Dictionary ([String: Any]) mit hierarchischen Keys wie ^TASK.001.TITLE und drei Basis-Operationen: SET, GET, KILL. Thread-safe über eine Serial DispatchQueue.

Das Projekt ist ein funktionierender Prototyp. Es hat keine Persistenz, keine Datenbank, keine Cloud-Anbindung. Die Daten leben nur im RAM und sind nach App-Neustart weg. Es ist ein Experiment — kein fertiges Produkt.

ARCHITEKTUR

Die App besteht aus 9 Swift-Dateien. Kein Framework, keine Dependencies, kein CocoaPods. Alles in einem Xcode-Projekt:

  • Kernel/TheBrain.swift — Singleton, [String: Any] Store, DispatchQueue, Score-Berechnung
  • Kernel/Syntax.swift — Typisierte Key-Pfade (BrainPath), DSL-Wrapper (iMOPS.SET/GET/KILL)
  • Kernel/TaskRepository.swift — Task anlegen, quittieren, ins Archiv verschieben
  • Kernel/ProductionTaskView.swift — SwiftUI: Offene Aufgaben + Quittierung
  • Kernel/RootTerminalView.swift — Router: liest ^NAV.LOCATION, rendert passende View
  • TerminalViews/HomeMenuView.swift — Hauptmenü mit Live-Score
  • TerminalViews/CommanderView.swift — Archiv-Einsicht, HACCP-Export als Text
  • TerminalViews/StaffGridView.swift — Zero-Waste: Überproduktion → Kantine
  • Kernel/iMOPS_OS_COREApp.swift — @main, ruft seed() auf

DER KERN: TheBrain.swift

Das Herzstück ist ein Singleton mit einem Dictionary. Keys beginnen mit ^ (wie MUMPS Globals) und sind hierarchisch aufgebaut. Der Zugriff ist per Serial Queue thread-safe. 

@Observable
final class TheBrain {
    static let shared = TheBrain()

    private var storage: [String: Any] = [:]
    private let kernelQueue = DispatchQueue(label: "imops.kernel.queue")

    func set(_ path: String, _ value: Any) {
        kernelQueue.sync { storage[path] = value }
    }

    func get<T>(_ path: String) -> T? {
        kernelQueue.sync { storage[path] as? T }
    }

    func kill(_ path: String) {
        kernelQueue.sync { storage.removeValue(forKey: path) }
    }
}

Die DSL-Schicht (Syntax.swift) macht die Nutzung lesbarer: 

// Task anlegen
iMOPS.SET(.task("001", "TITLE"), "MATJES WÄSSERN")
iMOPS.SET(.task("001", "STATUS"), "OPEN")

// Task abfragen
let title: String? = iMOPS.GET(.task("001", "TITLE"))

// Navigation (statt UIKit-Router)
iMOPS.GOTO("PRODUCTION")  // → setzt ^NAV.LOCATION

WORKLOAD-SCORE

Der "Meier-Score" berechnet die aktuelle Belastung der Brigade. Die Formel zählt offene Tasks, gewichtet sie, und berücksichtigt Standzeit (wie lange die älteste Aufgabe offen ist) und Personal. 

// Vereinfachte Formel:
totalLoad   = Summe aller offenen Task-Gewichte
fatigue     = 1.0 + (Stunden seit ältestem Task / 10)
capacity    = Anzahl Brigade-Mitglieder * 20

score = (totalLoad / capacity) * fatigue * 100
// Ergebnis: 0–100, wird live in der UI angezeigt
// > 40 = orange, > 70 = rot, Hintergrund glüht

Die UI reagiert auf den Score: Terminal-Titel wird rot, Hintergrund färbt sich ein, Zitate wechseln. Ein "Rush Hour"-Simulator injiziert 10 hochgewichtete Tasks zum Testen.

DENKBARE EINSATZGEBIETE

Der Kern von iMOPS — hierarchischer Store, atomare Operationen, Quittierung mit Zeitstempel — ist nicht auf Küchen beschränkt. Überall wo unter Druck dokumentiert, quittiert und koordiniert werden muss, wäre das Prinzip anwendbar. Aktuell ist nur Gastronomie implementiert. Der Rest ist Zukunftsmusik.

WARUM MUMPS?

MUMPS (Massachusetts General Hospital Utility Multi-Programming System) läuft seit den 1960ern in Krankenhäusern und Banken. Das US-amerikanische VA-Gesundheitssystem (VistA) nutzt es bis heute für Millionen Patientenakten.

Die Idee hinter iMOPS: wenn ein 60 Jahre altes System unter Hochlast in Krankenhäusern funktioniert, kann das Prinzip — hierarchische Keys, globaler Speicher, atomare Operationen — auch in einer Küche funktionieren, wo Bons verloren gehen und niemand weiß, wer was quittiert hat.

iMOPS ist keine MUMPS-Implementierung. Es borgt sich das Datenmodell (^GLOBAL.KEY.SUBKEY) und die Philosophie (alles im RAM, kein ORM, kein Schema), implementiert aber nur SET/GET/KILL in Swift.
